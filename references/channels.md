# 渠道手册：公司软口碑搜集的实操细节

本文件是 `company-soft-review` 技能的参考文档，记录检索词矩阵、每个渠道的可用路径、URL 规律、免登录技巧与已验证的坑。SKILL.md 只保留流程主干，细节以本文件为准。

---

## 0. 总原则

1. **归属验证高于一切**。匿名点评页（形如 `/moment/<纯数字ID>`）正文不显示公司名，搜索引擎靠关键词模糊匹配，错配率极高。任何一条点评/面经/评论，引用前必须单独打开确认页面底部的公司归属（公司名或公司页链接）。无法验证归属的一律弃用，宁可少一条，不可错一条。
2. **简称不替代全称，只作扩召回层**。收益与误配一起来，必须靠消歧闸门兜底（见第 1 节）。
3. **硬证据优先于软口碑**。劳动争议执行记录（当事人为自然人、案由为劳动争议）是口碑的最硬替代证据；JD 原文是公司自述，比任何匿名点评都硬。
4. **正面与负面冲突时不裁决**。并列呈现，标注时间差与样本量，给出三种可能解释（管理变化/部门差异/样本不足）。
5. **所有来源附 URL 与日期**，供用户复核。
6. **禁止编造**。性骚扰、白嫖成果这类指控若无命中，明确写"零命中"，不得用推测填充。

## 1. 检索词：四层矩阵与消歧闸门（开工第一件事）

### 1.1 为什么必须分层

员工在社交平台吐槽时**往往不写公司全称**——怕被同事搜到、怕被公司追责、嫌名字长。但简化到"简称"会撞车。实测对照（某企业管理咨询公司案例）：

| 检索词 | 结果 | 有效口碑 |
|---|---|---|
| 简称「字号 公司 避雷 加班 离职」 | 1 条撞车外地某同前缀教育公司、2 条通用 HR 普法文、2 条官网自吹 | **0 / 5** |
| 全称「工商全称 避雷 加班 离职」 | 职Q 公司页（79 条点评）、爱企查司法栏、猎聘、店长直聘 | **4 / 5** |

结论：**简称的收益和误配率是一起来的**。所以做法不是"把全称换成简称"，而是"全称打底 + 变体扩召回 + 锚点消歧"，且简称只在**社区类平台**投放。

### 1.2 脚本：一键生成四层矩阵

```bash
NODE=node  # 按自己的环境指定 Node 可执行文件路径
"$NODE" scripts/name-variants.js "某某市某某企业管理咨询有限公司" \
  --legal "法定代表人姓名" \
  --brand "品牌名/官网用名" \
  --product "产品名1,产品名2" \
  --selfname "员工自称/内部花名" \
  --addr "门牌号,写字楼名,片区路名" \
  --biz "核心业务词,岗位词1,岗位词2" \
  --out "<输出目录>"
```

输出三个文件：

| 文件 | 内容 |
|---|---|
| `name_variants.md` | 四层词表 + 歧义等级 + 平台分配 + 消歧规则 + 禁用清单 |
| `name_variants.json` | 结构化数据（`parts` 拆名结果 + `layers` 四层 + `keywords`） |
| `_keywords.txt` | 去重后的全部本体词，**可直接喂给 `capture.js`** |

不传任何锚点时脚本仍可跑（只出 L1 + L2 的推导部分），但**锚点越多、召回越准**——花 3 分钟补锚点是整个流程里性价比最高的一步。

### 1.3 四层定义与取词来源

| 层 | 取词来源 | 实操要点 |
|---|---|---|
| **L1 全称锚定** | 工商连接器（企查查/天眼查） | 必跑。招聘类平台（职Q/BOSS/职友集/猎聘）**只用这一层** |
| **L2 名称变体** | ① 字号：脚本自动从全称推导（地域+字号+行业+组织形式 → 字号）<br>② 品牌名：官网 `<title>`、公众号名、招聘页公司主页<br>③ **产品名**：官网"产品/解决方案"页、公众号历史文章、JD 里的项目名<br>④ **员工自称**：官网"企业文化"页、内刊名、团建活动名 | **收益最高的一层。** 产品名与员工自称专属性极强、几乎零碰撞，且只有内部人才会用——**命中即可高概率判定为真实员工发言**。实战案例：曾用产品名与员工自称（来自官网"企业文化"栏目）直接捞到内部人吐槽 |
| **L3 场景锚点** | ① 门牌：工商注册地址 + JD 里的实际工作地点<br>② 写字楼/园区名、片区路名<br>③ 业务词、岗位词（从 JD 抓） | **对付"完全不带公司名"的吐槽，是必需项不是加分项。** 实战中曾有一条 262 赞笔记标题与正文均无公司名，全靠场景锚点捞到 |
| **L4 人名锚点** | 法定代表人、实际控制人、高管（工商连接器） | 搜完切"用户"标签找企业号/员工号（`usertab.js`）。也用于 L2 组合共现 |

### 1.4 平台分工（不可混用）

| 平台类型 | 平台 | 投放层 | 原因 |
|---|---|---|---|
| **招聘类** | 职Q / BOSS直聘 / 职友集 / 猎聘 | **只用 L1** | 平台已做公司主体绑定，全称直达主体页，简称反而丢精度 |
| **社区类** | 小红书 / 知乎 / 贴吧 / NGA | **L1+L2+L3+L4 全跑** | 用户自发发言、不愿写全称，简称在此才有收益 |
| **商务类** | 企查查 / 天眼查 / 爱企查 | **只用 L1 或统一社会信用代码** | 精确匹配，简称会撞车 |

### 1.5 消歧闸门（三条，缺一不可）

**R1 共现规则**——2 字简称单独命中**不予采信**，必须与至少一个锚点同现。落地做法：用组合词检索，如 `字号 + 主营业务词`、`字号 + 门牌路名`、`字号 + 品类词`。脚本会自动生成一批"字号 × 锚点"组合词。

**R2 碰撞检测**——先跑一轮全称，把结果中冒出的**形近字或同前缀的其他主体**列成碰撞清单，后续所有简称检索的结果都要对照该清单剔除。已知实战碰撞：

| 检索词 | 撞到的无关主体 | 碰撞类型 |
|---|---|---|
| A 公司字号 | 外地某**同前缀**教育公司 | 同前缀 |
| B 公司字号 | 某形近字号企业管理公司 | 形近字 |

**R3 归属验证（一票否决）**——任何要写入报告的内容，必须能落到公司主体上。可接受的硬指代：
- 职Q 页面的 `companyDetail/<ID>` 链接、页面底部公司名
- 笔记中出现公司名 / 门牌号 / 写字楼名 / 产品名 / 员工自称
- JD 原文（公司自述，见 BOSS直聘节）

不可接受：仅凭关键词匹配、仅凭"名字像"、仅凭地域相近。**反例**：搜"B 公司字号 + 面试体验"返回的首条"刷KPI / 单休 / 试用期无社保"点评，实际归属是一家毫不相关的**建设集团**——搜索引擎把匿名点评页模糊匹配给了查询词。

### 1.6 禁用词（勿浪费查询）

| 禁用 | 原因 |
|---|---|
| 拼音首字母（CDYJ / PJ） | 中文语境无人这么写，噪音≈100% |
| 单字简称 | 歧义爆炸 |
| 纯通用词（咨询/科技/服务） | 无主体指向 |

**例外**：超知名企业的花名（鹅厂 / 开水团 / 宇节）本身已是唯一指代，可单独搜。

### 1.7 投放顺序

**L1 → L2（产品名/员工自称优先于字号简称）→ L4 人名 → L3 场景锚点。**

L1/L2 全军覆没时**必须补跑 L3** 才能下"零口碑"结论——否则只能说"未在已检索层发现"，不能说"没有"。

## 2. 职Q（智联招聘，zq.zhaopin.com）—— 最重要渠道

> **用词层：只用 L1 全称**（平台已做主体绑定，全称直达主体页）。

### URL 规律（已验证）

- 公司主页：`https://zq.zhaopin.com/companyDetail/<公司ID>`
- **免登录关键**：在公司ID 后拼 `-true` 进入服务端渲染子页：
  - `.../companyDetail/<ID>-true/mianshi/` → 面经全文（通常 30-40 条，可分页）
  - `.../companyDetail/<ID>-true/gongzi/` → 员工自报工资（含岗位与金额）
  - `.../companyDetail/<ID>-true/wenda/` → 问答区（"工作体验""是不是中介"类关键问题常在这里）
  - `.../companyDetail/<ID>-true/dianping/` → 点评列表（**只渲染第 1 条，其余需登录**）
- 点评/动态详情页：`https://zq.zhaopin.com/moment/<数字ID>`——正文不显示公司名，**必须验证归属**。
- 问答详情：`https://zq.zhaopin.com/question/<数字ID>`。
- 子页 ID 模式：`companyDetail/<ID><字母数字后缀>`（如 CZ432485010D00321659284）可直达某条内容。

### 找公司 ID

WebSearch：`site:zq.zhaopin.com <公司全称>` 或 `<公司名> 职Q 点评 面试`。搜索结果里的 companyDetail 链接即含 ID。

### 已知局限

- 点评列表免登录只能看 1 条；**其余内容的量级差异可写进报告的"局限声明"**（如"该司共有 84 条点评，免登录可见 3 条，其余需用户自行登录查看"），并引导用户用自己账号登录看（不消耗任何额度）。
- 找看准网（kanzhun）**已于 2024 年 9 月关闭**，不再是可用渠道。

## 3. 小红书 —— 唯一需要浏览器接管的渠道（重点）

> **用词层：L1+L2+L3+L4 全部投放**（这是本渠道成为核心差异化渠道的原因）。

### 为什么必须接管浏览器

- 未登录访问 `/search_result` 与 `/explore`：**整站 302/登录墙**，对照组实验（搜必然有海量结果的通用词）证明未登录一概隐藏结果。
- 小红书屏蔽所有主流搜索引擎：Bing/百度 `site:xiaohongshu.com` 对任何词都返回 0 条真实笔记。
- 直接访问 `/explore/<noteId>` 不带 `xsec_token` 会被拦："当前笔记暂时无法浏览"。token 只能从**搜索结果页点击**获得，且为**单次有效**。

### 登录接管流程（用户已同意的前提下）

1. 让用户**双击** `scripts/start_debug_chrome.bat` —— 启动独立 Chrome（端口 9222、独立 profile `%LOCALAPPDATA%\xhs_debug_prof`，不影响用户日常 Chrome），用户扫码登录小红书。
2. 用户回复"登录完成"后，用 playwright `connectOverCDP('http://127.0.0.1:9222')` 接管。**注意：绝不能对 CDP 连接的 browser 调 close()**，会关掉用户的窗口；脚本一律用 `process.exit(0)` 结束。
3. 验证登录态：检查 `hasAvatar=true` 且 `hasLoginBtn=false`（cookie 存在 ≠ 登录，访客 session 也有 cookie，用 cookie 判断会误判）。
4. 完成后提醒用户退出登录并删除 `%LOCALAPPDATA%\xhs_debug_prof`（内含登录态）。

### 环境要求

- Node：16+（`node` 可执行文件需在 PATH 中，或自行指定路径）
- `NODE_PATH` 指向装有 playwright 的 `node_modules` 目录（脚本通过 `connectOverCDP` 接管浏览器，不下载浏览器内核）
- 部分环境下运行前需 `unset NODE_OPTIONS`（沙箱注入的 NODE_OPTIONS 可能破坏 playwright）

### 脚本工具链（scripts/ 目录，按执行顺序）

| 脚本 | 用途 | 用法 |
|---|---|---|
| `name-variants.js` | **先跑这个**：生成四层检索词 → `_keywords.txt` | 见第 1.2 节 |
| `capture.js` | 多关键词搜索列表抓取（30 条/词） | 关键词写入脚本同级 `_keywords.txt`（每行一个），`node capture.js <输出目录>` |
| `deepscroll.js` | 深度滚动加载全量卡片 + 按负面关键词自动筛选 | `node deepscroll.js <输出目录> <起始卡> <数量>`（关键词读 `_keywords.txt`） |
| `targeted2.js` | **单次加载搜索页 + 同页连续按作者名点击目标卡片**，读正文(#detail-desc)+评论+截图 | `node targeted2.js <输出目录> <卡片起始> <作者名1> [作者名2 ...]` |
| `traverse.js` | 逐张点开前 N 张卡片读详情 | `node traverse.js <输出目录> <起始> <数量>` |
| `comments.js` | 对指定笔记 URL（须带有效 xsec_token）拉取评论区 | `node comments.js <输出目录> <完整URL> <标签> [滚动次数]` |
| `dl.js` | 下载笔记图片（xhscdn，带 Referer） | `node dl.js <traverse.json> <图片输出目录> <前缀>` |
| `usertab.js` | 搜索后切"用户"标签（找企业号/员工号） | 关键词写入 `_keywords.txt`，`node usertab.js <输出目录>` |

### 关键词投放策略

- **四层全投**。优先顺序：**产品名/员工自称（L2）→ 字号（L2）→ 法人名（L4）→ 场景锚点（L3）**。
- 产品名/员工自称命中即可高概率判定为内部人发言（外部人不知道这些词）。
- 法人名搜索后**切"用户"标签**，找企业号/员工号（员工吐槽常以个人视角出现、不带公司全称）。
- 负面筛选关键词建议：避雷、加班、离职、拖欠、PUA、实习、面试、工资、仲裁、维权。
- **L1/L2 都无果时，用 L3 场景锚点（门牌/写字楼/片区路名/岗位词）再扫一轮**，然后才能下"零口碑"结论。

### 评论区与正文同级优先

员工用简称吐槽**极少出现在标题里**（怕被搜到），大量藏在**评论区**：

- 水军实锤、离职自述、待遇落差、公司名确认往往都在评论里。
- **赞低评高必展开读**（如 2 赞 118 评论 = 评论区有激烈争论）。
- L3 场景锚点捞到的"无公司名"笔记，其价值**全部在评论区**——正文没名字，评论里可能有人点出公司名。

### 已验证的坑（务必遵守）

1. **搜索结果是动态个性化的，每次加载顺序都会洗牌**。要点进特定卡片必须用 `targeted2.js`（一次加载、同页连续点击），不要"重新加载搜索页再找"。
2. **xsec_token 单次有效**。`traverse.json`/`deep_notes.json` 里存的带 token URL 只能马上用，过期后须重新从搜索页点击获取。
3. **弹层详情页里 `document.body.innerText` 仍是搜索列表文本**，笔记正文要取 `#detail-desc`；DESC 与 BODY 要分清。
4. **imgs 数组会混入弹层侧边"相关推荐"的封面图**，下载后逐张核对是否属于目标笔记。
5. 图片为 webp/jpg 混合，下载带 `Referer: https://www.xiaohongshu.com/`，否则 CDN 拒绝。
6. 截图（弹层）比正文更全：含标签、日期、赞藏评数，逐张读图（多模态识别）。
7. 排查进程时 Git Bash 下 `tasklist //FI "..."` 会静默失效，用 `tasklist | grep -i chrome` 或 wmic。
8. 自动化环境启动的 GUI 进程会被清理（日志停在半途、进程消失）——所以**必须由用户双击 bat 启动浏览器**。

### 水军/刷评识别特征（实战案例沉淀）

- 两个不同地区 IP 的账号在**同一天**发布**一字不差**的同一句文案 → 水军实锤。
- 正面笔记**发布日期高度集中**（如 6 天内 10+ 条）、赞数极低（个位数）、话术模板化（抽象赞美，无具体事例）。
- 笔记作者或评论者公开指控"冒出十几条大号小号夸好"→ 作者本人举证。
- 第三方独立用户佐证"褒贬不一，还有水军"。
- 反向校准：真实差评的特点是**细节具体**（离职场景、待遇落差、驻地经历），好评全是抽象赞美。

## 4. BOSS直聘（zhipin.com）

> **用词层：只用 L1 全称。**

- 公司点评页：`https://www.zhipin.com/gongsi/review/<公司ID>.html`——内容多为公司宣传帖与问答，负面少，可作对照。
- 找 ID：`site:zhipin.com <公司名>`。
- **JD 原文是最硬的软信息**：任职要求里"能接受阶段性加班""抗压能力好"是公司自述承认加班；对比同批岗位 JD（如"朝九晚六双休"）可判断部门差异。
- **同时是 L3 锚点的重要来源**：JD 里的实际工作地点（写字楼/园区）与岗位名，直接用作场景锚点。
- 大量内容需登录，免登录只能看摘要。

## 5. 职友集（jobui.com）

> **用词层：只用 L1 全称。**

- 公司页 `https://www.jobui.com/company/<ID>/`，评论子页 `/comment/`。
- 价值：招聘数量趋势、工资分布；点评内容少。
- 找 ID：`site:jobui.com <公司名>`。

## 6. 猎聘（liepin.com）

> **用词层：只用 L1 全称。**

- 主要看 JD 与公司标签（如"双休"标签）；点评功能弱。搜索 `<公司名> 猎聘` 即可。

## 7. 脉脉（maimai.cn）

> **用词层：L1，命中后可用 L2 补充。**

- 实名/半实名职场社区，但未登录几乎全墙；搜索 `<公司名> 脉脉` 看是否有公开被索引的帖子，命中通常极少。命中则标注"需用户自行登录查看全文"。

## 8. 知乎 / 贴吧 / NGA 等公开社区

> **用词层：L1+L2+L3+L4 四层全跑**（与小红书同类：用户自发发言、不愿写全称）。

- WebSearch 组合方式：
  - **主体 × 关注点**：`<全称> 加班 离职`、`<字号> 仲裁`、`<品牌名> 待遇`
  - **锚点 × 关注点**：`<写字楼名> 公司 避雷`、`<岗位词> 成都 加班`
  - **四层词轮换**，不要只跑全称。
- 时间筛选优先近 1-2 年（`freshness=y2`），旧帖结论可能已失效，引用时标注时间差。
- NGA/贴吧的**二手转述**（"网上的留言说…"）只能标为低可信度线索，注明时间差。
