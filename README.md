# company-soft-review · 公司软口碑尽调技能

> 适合 AI Agent（WorkBuddy / Claude Code / Codex 等支持 SKILL.md 规范的工具）使用的公司口碑尽调技能。
> 工商数据告诉你"这家公司存不存在"，这个技能告诉你"这家公司值不值得去"。

## 它解决什么问题

查一家公司，企查查/天眼查能给你注册资本、司法风险、参保人数——但查不到这些：

- 加班多不多？是不是单休/大小周？
- 有没有刷 KPI 面试（约你过去凑面试量，根本不打算要人）？
- 试用期缴不缴社保？工资拖不拖？
- 网上的好评是真员工说的，还是水军刷的？
- 那条"XX这个公司能去吗"的匿名吐槽，说的是不是这家公司？

这些"软口碑"散落在职Q、BOSS直聘、职友集、猎聘、脉脉、知乎、贴吧、小红书里。这个技能把搜集、消歧、验证、分级的完整方法论沉淀成了 Agent 可执行的流程。

## 核心方法论（这个技能真正的价值所在）

### 1. 四层关键词矩阵

员工吐槽时**往往不写公司全称**——怕被同事搜到、怕被追责。只用全称搜会漏掉大量真实口碑，只用简称搜会撞出一堆无关公司。解法是分层投放：

| 层 | 内容 | 价值 |
|---|---|---|
| **L1 全称锚定** | 工商全称 | 基准。招聘类平台唯一用词 |
| **L2 名称变体** | 字号简称、品牌名、**产品名/内部黑话、员工自称** | **收益最高**。产品名命中即高概率真实员工 |
| **L3 场景锚点** | 门牌/写字楼/园区、业务词、岗位词 | 专捞"完全不带公司名"的匿名吐槽 |
| **L4 人名锚点** | 法人、实控人、高管 | 员工吐槽常以人名视角出现 |

配套脚本 `scripts/name-variants.js`：输入工商全称 + 锚点，一键生成四层词表、歧义等级、平台投放分配表。

### 2. 消歧闸门（R1/R2/R3，防止张冠李戴）

- **R1 共现规则**：2 字简称单独命中不予采信，必须与至少一个锚点同现
- **R2 碰撞检测**：形近字、同前缀的其他主体立即标红单列
- **R3 归属验证（一票否决）**：任何写入报告的点评必须单独打开验证公司归属——匿名点评页正文不显示公司名，搜索引擎模糊匹配的错配率极高

### 3. 证据分级与交叉验证

S 级实锤 → A 级可信 → B 级线索 → 疑似单列，每条标注来源检索层与消歧结果。过不了闸的一律降级或弃用，且在报告中单列"已排除的误配"及理由。

正负面证据冲突时不裁决，并列呈现并给出解释空间（管理变化/部门差异/样本不足）。

**零口碑 ≠ 好口碑**：小公司无人评论是结构常态，如实标注，结论回落到硬数据。

### 4. 水军/刷评识别

不同 IP 账号同日发一字不差同文案 = 实锤；正面贴日期高度集中 + 赞数个位数 + 话术模板化 = 高度可疑。反向校准：真实差评细节具体，水军好评全是抽象赞美。

### 5. 小红书站内深挖（核心差异化渠道）

小红书屏蔽所有搜索引擎，必须走 CDP 浏览器接管。配套 8 个 playwright 脚本：关键词投放 → 深度滚动 → 同页连续点击读正文+评论+截图 → 评论补充 → 图片下载 → 用户标签查企业号。所有坑位（动态洗牌、xsec_token 单次有效、弹层取 `#detail-desc`）都已踩平。

## 安装

### WorkBuddy

```bash
# Windows
git clone https://github.com/1stella-koi/company-soft-review.git "%USERPROFILE%/.workbuddy/skills/company-soft-review"

# macOS / Linux
git clone https://github.com/1stella-koi/company-soft-review.git ~/.workbuddy/skills/company-soft-review
```

或直接下载仓库 ZIP，解压到 `~/.workbuddy/skills/` 目录下（保证目录结构为 `skills/company-soft-review/SKILL.md`）。

### 其他 Agent 工具

任何支持加载 Markdown 技能文件的 Agent（Claude Code / Codex CLI 等）都可将本仓库作为技能目录挂载，`SKILL.md` 即主流程。

## 依赖

- **纯文字渠道轮询**（职Q/BOSS/职友集/猎聘/知乎/贴吧）：零依赖，Agent 自带 WebSearch/WebFetch 即可
- **小红书深挖**：Node 16+ 与 [playwright](https://playwright.nodejs.org/)（仅用 `connectOverCDP` 接管浏览器，不下载浏览器内核），本机需装 Chrome

## 使用

装好之后直接用自然语言触发，例如：

```
成都一家叫"某某咨询"的公司给我发了 offer，这家公司值得去吗？
帮我查查 XX 公司的口碑，网上员工评价怎么样？
```

Agent 会自动：锚定工商主体 → 生成四层检索词 → 逐渠道搜集 → 消歧验证 → 产出口碑尽调报告（含证据分级、误配清单、局限声明、官方免费复核渠道）。

> 建议配合工商信息连接器（企查查/天眼查 MCP）使用，形成"硬证据 + 软口碑"完整报告；没有连接器时技能会单独出口碑报告并标注缺硬数据维度。

## 边界与红线

- 不绕过付费墙、不伪造平台签名、不抓取付费报告产品
- 涉及登录态的操作（小红书扫码）必须先征得用户明确同意；用户浏览器 cookie/profile 一律不碰
- 匿名指控无信源时写"零命中"，不推测、不渲染
- 报告中所有结论可按 URL 自行复核

## 文件结构

```
company-soft-review/
├── SKILL.md                  # 主流程与规则（Agent 的入口文件）
├── references/
│   └── channels.md           # 七渠道实操细节、URL 规律、坑位清单、水军特征
└── scripts/
    ├── name-variants.js      # 四层检索词矩阵生成器
    ├── start_debug_chrome.bat# 双击启动独立 Chrome（9222 调试端口）登录小红书
    ├── capture.js            # 关键词搜索列表抓取
    ├── deepscroll.js         # 深度滚动全量卡片 + 疑似项筛选
    ├── targeted2.js          # 同页连续点击目标卡片，读正文+评论+截图
    ├── traverse.js           # 逐张点开前 N 张卡片读详情
    ├── comments.js           # 指定笔记 URL 拉评论区
    ├── dl.js                 # 下载笔记图片
    └── usertab.js            # 搜索后切"用户"标签找企业号/员工号
```
